# CultivaNode current release ledger

**Evidence snapshot:** 18 November 2026 (Africa/Lagos). **GitHub implementation baseline:** `main` at `3323d6b194c2711fac7127abce1fa8382ce474f7` (Batch 02.3 merged via [PR #9](https://github.com/farmconnect-ux/cultivanode/pull/9)). **Hosted Supabase project:** CultivaNode, `vqbtnftnxyfaembwgfrk` (Production; last verified migration snapshot `20261025212753_fk_indexes_rls_initplan` on 3 November 2026). **Owner:** product and engineering maintainers.

This is the canonical release-status record for the product. A feature is not release-ready merely because its code exists. Each state is tracked separately:

- **Repository code:** implementation present on `main`.
- **Automated tests:** workspace unit/typecheck/lint/build checks passing in CI.
- **Local Supabase CI:** migrations, pgTAP (`21` files, `750` assertions), concurrency, Storage API, and PostgREST RPC checks passing against isolated local Supabase in CI.
- **Hosted Staging / Production migration:** schema/seed migration confirmed applied to the connected hosted Supabase project (unverified/untouched since the 3 November 2026 snapshot).
- **Vercel Preview / Production:** recorded GitHub/Vercel deployment state for the PR or `main` commit.
- **Feature switch:** live Supabase `feature_flags` value at the latest verified snapshot; a missing switch defaults off in the app.
- **Physical Android / iOS device test:** recorded real-handset result. Automated tests and APK builds do not count as a handset pass.
- **Live external payment gateway:** verified end-to-end callback with real Paystack/Flutterwave test or live gateway events.
- **Field pilot:** evidence of use with real farmers/providers. Database rows alone do not establish that records came from a field pilot.

## Release gates

1. Close the exposure gap before inviting real users: replace test-only SMS and identity providers with verified live configuration, or close `marketplace_live` until that is done.
2. Review and apply the eight post-25-Oct migrations (`20261103000000` through `20261118010000`) to hosted Staging and Production through the normal reviewed migration workflow; then confirm the deployed function/schema versions and flags.
3. Review the 12 unmerged commits on `security/batch-01-marketplace-hardening` (`8ee4f43..a8e47dc`, 5 additional marketplace migrations and fulfilment/notification fixes) in a dedicated PR.
4. Reconcile `ai_photo_diagnosis=ON` with the agronomy review gate. Keep advice claims and photo diagnosis behind a verified, tested release decision.
5. Run and record real-device journeys on supported Android and iOS devices and weak connectivity, including OTP, farm entry, hiring GPS/proof, native role/document uploads, checkout, order/job disputes, and retry behavior, plus live payment gateway callback tests.
6. Record pilot provenance and outcomes: distinguish seeded/demo/test records from real users and jobs, then track completion, disputes, repeats, and support interventions.
7. Re-run Supabase security/performance advisors after hosted migrations and document disposition of each release-relevant finding.

Update this ledger only when evidence changes. Keep code, schema, deployment, feature flag, device, and pilot statuses separate.
